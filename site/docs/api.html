Facilitator API

Base URL https://x402.incentiv.io. It follows the x402 v2 facilitator API for the network eip155:24101 and the schemes incentiv-eoa-tx and incentiv-userop. The full rules are in the protocol spec.

Endpoints

Method and pathPurpose
GET /supportedSchemes and extensions on offer
POST /verifyCheck a signed payment without changing any state
POST /settleSubmit the payment and wait for its receipt (up to 60 seconds)
GET /healthRPC and bundler status
GET /discovery/resourcesList cataloged paid resources (only when the facilitator runs with discovery on)
GET /discovery/searchSearch cataloged resources (only with discovery on)

GET /supported

curl https://x402.incentiv.io/supported
{
  "kinds": [
    { "x402Version": 2, "scheme": "incentiv-eoa-tx", "network": "eip155:24101" },
    { "x402Version": 2, "scheme": "incentiv-userop", "network": "eip155:24101" }
  ],
  "extensions": [],
  "signers": { "eip155:24101": [] }
}

extensions lists "bazaar" only when discovery is on. signers is empty because the facilitator holds no signing key.

POST /verify

curl -X POST https://x402.incentiv.io/verify \
  -H "content-type: application/json" \
  -d @payment.json

Request body, for an incentiv-eoa-tx payment of 0.01 USDC:

{
  "x402Version": 2,
  "paymentPayload": {
    "x402Version": 2,
    "resource": {
      "url": "https://api.example.com/weather",
      "description": "Current weather",
      "mimeType": "application/json"
    },
    "accepted": {
      "scheme": "incentiv-eoa-tx",
      "network": "eip155:24101",
      "amount": "10000",
      "asset": "0x16e43840d8D79896A389a3De85aB0B0210C05685",
      "payTo": "0xYourIncentivAddress",
      "maxTimeoutSeconds": 120,
      "extra": {}
    },
    "payload": {
      "signedTransaction": "0x02f8cb825e25…"
    }
  },
  "paymentRequirements": {
    "scheme": "incentiv-eoa-tx",
    "network": "eip155:24101",
    "amount": "10000",
    "asset": "0x16e43840d8D79896A389a3De85aB0B0210C05685",
    "payTo": "0xYourIncentivAddress",
    "maxTimeoutSeconds": 120,
    "extra": {}
  }
}
  • paymentRequirements is the option the buyer chose from the seller's PAYMENT-REQUIRED header. paymentPayload.accepted must equal it.
  • paymentPayload is the buyer's PAYMENT-SIGNATURE header, base64-decoded.
  • For incentiv-userop, extra is { "entryPoint": "0x3eC61c5633BBD7Afa9144C6610930489736a72d4" } and payload holds userOperation, userOpHash, paymentId and validUntil. See the spec.

Response (HTTP 200 for every payment outcome):

{ "isValid": true, "payer": "0x…" }
{
  "isValid": false,
  "invalidReason": "insufficient_funds",
  "invalidMessage": "USDC balance 0 is below 10000"
}

POST /settle

The same body as /verify. It repeats every check, submits the payment, and waits for a receipt.

curl -X POST https://x402.incentiv.io/settle \
  -H "content-type: application/json" \
  -d @payment.json
{
  "success": true,
  "transaction": "0x…",
  "network": "eip155:24101",
  "payer": "0x…",
  "amount": "10000"
}
{
  "success": false,
  "errorReason": "insufficient_funds",
  "errorMessage": "USDC balance 0 is below 10000",
  "payer": "0x…",
  "transaction": "",
  "network": "eip155:24101"
}
  • Serve the content only after success: true.
  • After settle_timeout, retry the same payload. Do not ask the buyer to sign again.
  • A payment is reported as a success to at most one /settle call. Others get already_settled or already_settling.

GET /health

200 { "status": "ok", "rpc": "ok", "bundler": "ok" }
503 { "status": "degraded", "rpc": "down", "bundler": "ok" }

Discovery

PathQueryResponse
/discovery/resourcestype, payTo, scheme, network, limit (at most 100), offset{ x402Version: 2, items, pagination }
/discovery/searchquery (at most 200 characters), plus the same filters and limit{ x402Version: 2, resources, partialResults, pagination: null }

A resource is cataloged when a payment for it settles and its route declared Bazaar discovery info. There is no manual registration. Listings are not authenticated: the details of an entry come from whoever pays. Do not trust them without checking the resource's live 402.

Errors and limits

StatusBodyWhen
400{"error":"invalid_request"}No paymentPayload or paymentRequirements, or a bad JSON body
400{"error":"unsupported_scheme"}A scheme, network or x402 version the facilitator does not serve
404{"error":"not_found"}A path the service does not serve
429{"error":"rate_limited"}Over the per-address limit: 120 /verify, 60 /settle and, with discovery on, 120 /discovery/* calls per minute (defaults)
500{"error":"internal_error"}An unexpected error. The body never carries a stack trace.

The request body is limited to 64 KB.
