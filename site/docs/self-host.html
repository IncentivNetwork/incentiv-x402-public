Run a facilitator

Use https://x402.incentiv.io, or run your own instance. The facilitator holds no private key. It only submits payments that buyers already signed.

git clone https://github.com/IncentivNetwork/incentiv-x402-public
cd incentiv-x402-public
docker build -t incentiv-x402-facilitator .
docker run -p 4020:4020 -v x402-data:/data incentiv-x402-facilitator
Run exactly one instance, with persistent storage at /data. The facilitator keeps in memory which payments are being settled and which payers are mid-payment. Two instances would each believe they are the only claimant, and one payment could be reported as a success twice. Without persistent storage, a payment whose settle timed out just before a restart is refused on retry (already_settled), so its payer is charged but not served.

Configuration

All settings are environment variables. Defaults are Incentiv mainnet.

Operating notes

  • Health check. GET /health returns 200 when the RPC and the bundler both answer, and 503 otherwise. The image has a built-in container health check.
  • TLS. Terminate TLS at a load balancer or proxy in front.
  • Shutdown. On SIGTERM it stops accepting requests and waits up to 70 seconds, because a settle can wait up to 60 seconds for a receipt. Set your orchestrator's stop timeout to at least 75 seconds.
  • Logs. One JSON line per settle (event: "settle", scheme, success, reason, transaction, payer, amount) and per start or stop, on stdout.

After deploying

  1. Open /health and /supported on your host.
  2. Run npm run e2e against it with a funded test payer. It spends real funds on mainnet.
  3. Give sellers your URL to use as their facilitator.
