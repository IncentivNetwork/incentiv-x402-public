Seller quickstart

Protect an Express route and receive USDC on Incentiv.

Prerequisites

RequirementNotes
An Incentiv addressIt receives the USDC
Node.js 22.18 or later
An API to protectExpress, Next.js or Hono

Steps

  1. Install. 
    npm install @incentiv/x402

    It brings @x402/core, @x402/express, @x402/extensions and @x402/fetch with it.

  2. Protect a route. Point the resource server at the public facilitator and register both schemes. 
    import express from "express";
import { paymentMiddleware } from "@x402/express";
import { HTTPFacilitatorClient, x402ResourceServer } from "@x402/core/server";
import { IncentivEoaTxScheme, IncentivUserOpScheme } from "@incentiv/x402";

const NETWORK = "eip155:24101";
const server = new x402ResourceServer(
  new HTTPFacilitatorClient({ url: "https://x402.incentiv.io" }),
);
server.register(NETWORK, new IncentivEoaTxScheme());
server.register(NETWORK, new IncentivUserOpScheme());

const pay = (scheme: string) => ({
  scheme,
  network: NETWORK,
  payTo: "0xYourIncentivAddress",
  price: "$0.01",
  maxTimeoutSeconds: 120,
});

const app = express();
app.use(
  paymentMiddleware(
    {
      "GET /weather": {
        accepts: [pay("incentiv-eoa-tx"), pay("incentiv-userop")],
        description: "Current weather",
        mimeType: "application/json",
      },
    },
    server,
  ),
);
app.get("/weather", (_req, res) => res.json({ city: "Kyiv", tempC: 21 }));
app.listen(4021);
  3. Test the 402 response. 
    curl -i http://localhost:4021/weather

    You should get HTTP 402 with a PAYMENT-REQUIRED header. It is base64 JSON that lists the price and the schemes you accept.

  4. Test the facilitator. 
    curl https://x402.incentiv.io/health
curl https://x402.incentiv.io/supported
  5. Test a paid request. Use the buyer quickstart with a small amount of USDC and a little CENT.

Options

SettingRule
schemeOffer one or both: incentiv-eoa-tx, incentiv-userop. A buyer pays with the first one it supports.
priceIn USD, paid in USDC.
payToYour Incentiv address. The facilitator never holds the funds.
maxTimeoutSecondsCapped at 300. 120 is a good default.
extra.paymentFlowSet "upfront" on each payment option for routes that do expensive work or have side effects.
Serve only after settlement. By default the handler can start before settlement finishes. With paymentFlow: "upfront", the payment settles before the handler starts, and a later handler failure does not refund it.

Other frameworks

The resource server and the payment options are the same as in the Express example.

Next.js

npm install @incentiv/x402 @x402/next

app/api/weather/route.ts:

import { NextRequest, NextResponse } from "next/server";
import { withX402 } from "@x402/next";
import { HTTPFacilitatorClient, x402ResourceServer } from "@x402/core/server";
import { IncentivEoaTxScheme, IncentivUserOpScheme } from "@incentiv/x402";

const NETWORK = "eip155:24101";
const server = new x402ResourceServer(
  new HTTPFacilitatorClient({ url: "https://x402.incentiv.io" }),
);
server.register(NETWORK, new IncentivEoaTxScheme());
server.register(NETWORK, new IncentivUserOpScheme());

const pay = (scheme: string) => ({
  scheme,
  network: NETWORK,
  payTo: "0xYourIncentivAddress",
  price: "$0.01",
  maxTimeoutSeconds: 120,
});

const handler = async (_req: NextRequest) =>
  NextResponse.json({ city: "Kyiv", tempC: 21 });

export const GET = withX402(
  handler,
  {
    accepts: [pay("incentiv-eoa-tx"), pay("incentiv-userop")],
    description: "Current weather",
    mimeType: "application/json",
  },
  server,
);

Discovery (optional)

Declare discovery info, and a facilitator that runs with discovery on catalogs the route after its first paid request. Agents then find it through /discovery/resources and /discovery/search. No registration is needed. A facilitator that offers discovery lists bazaar under extensions in its /supported answer; check /supported to see whether the public one does.

import { bazaarResourceServerExtension, declareDiscoveryExtension } from "@x402/extensions/bazaar";

server.registerExtension(bazaarResourceServerExtension);
// in the route config:
//   serviceName: "Example Weather",
//   tags: ["weather"],
//   extensions: { ...declareDiscoveryExtension({ output: { example: { city: "Kyiv", tempC: 21 } } }) },

The merchant sees the outcome in the facilitator's EXTENSION-RESPONSES header: bazaar.status is success or rejected.

Errors

The facilitator answers HTTP 200 with a reason code, for example insufficient_funds, payment_expired or settle_timeout. After settle_timeout, retry the same payload. See the reason codes.
